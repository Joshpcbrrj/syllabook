# Book: the parts every book has

Every book answers the three reasons self-learners give up: no **direction** (where to start, how much is left), no **feedback** (am I getting it right?) and no **consistency**. The parts below exist for that.

**Who does what:** `build.py` generates the map with links, the navigation between chapters, the glossary links, the answers appendix of the EPUB and the folder lists. You write the texts. Never write by hand what a script generates.

## Files

```text
<book>/
  README.md                 ← the book's front page (§1)
  book.yaml
  chapters/
    00-<how-to-study>.md    ← chapter 0 + placement test (§2, §3)
    01-<slug>.md ...        ← chapters (TEACHING.md)
    NN-<mock-exam>.md       ← final mock exam (§5)
    <glossary>.md           ← glossary (§6)
  img/
    c00-<book-on-one-page>.svg  ← the book on one page (§4), from img/_source/c00-<...>.yaml
  projects/
```

File slugs: lowercase ASCII, hyphens, up to ~48 characters, in the book language (`00-como-estudar-este-livro.md`).

## 1. README (the front page)

In this order: cover image; title and subtitle; one paragraph on who it is for and what they will be able to do; **Start here** (links to chapter 0 and the placement test); **📇 The book on one page** (§4, you write it); the book map (the text table of contents with links, generated by `build.py`); **About this book** (§7); errata; links to other languages, if any.

## 2. Chapter 0: How to study this book

The book on one page (§4) near the top, then at most one page of text:

- how the book is organized (parts, the `🔎` optional sections, where the answers are);
- four study techniques in one line each: answer before looking; come back on the suggested days; explain it in your own words; mix old and new exercises;
- a table with three paces, computed from the chapter times in `book.yaml`:

  | Pace | Per day | Finish in |
  | --- | --- | --- |
  | Light | ~20 min | <weeks> |
  | Medium | ~40 min | <weeks> |
  | Intense | ~90 min | <weeks> |

- how to use the reviews, the AI tutor prompts and the mock exam.

## 3. Placement test

At the end of chapter 0: 6–10 questions, each tied to a chapter in `book.yaml`, answers hidden. Then a routing table: "Got questions 1–3 right? Start at chapter 4." Readers who know nothing start at chapter 1 without taking it.

## 4. The book on one page and the section cheat sheets

**The book on one page** (every book, required): the whole book in one `cards` diagram, so the reader sees at a glance where they are going and, later, revises in one look.

- **One card per chapter** (up to 12; with more chapters, one card per part or per pair of neighbouring chapters), in reading order. Card title: a short title only (`Por que Git`): `diagram.py` writes the number before it (`1. Por que Git`); for a card that covers several chapters, give `number: "1-2"`. Three items per card: what the reader must remember or be able to do (`revert no que foi enviado`, `G→C a 80 bpm`), never topic names (`Comandos de desfazer`). An icon per card that matches it.
- Title of the diagram: `<label "The book on one page">: <the journey in a few words>` ("O livro numa página: do primeiro commit ao site publicado").
- Write the spec in `img/_source/c00-<label slug>.yaml` and draw it with `diagram.py` (never by hand); the alt text lists every card with its items.
- Put it in the README under `## 📇 <label>`, right after **Start here**, and at the start of chapter 0 (after the opening paragraph), so the EPUB, the website and the Notion copy have it too.
- Write it in the fixed parts step, from the chapter summaries in `book.yaml` (`progress`); update it when a review changes what a chapter teaches. The whole-book audit refuses a book without it.

**Section cheat sheets** (one per part of the book, every 3–4 chapters): at the start of the part's first chapter, a `cards` diagram of that part only (more detail than the book on one page: up to 12 cards for 3–4 chapters), followed by the list of links to the part's chapters.

## 5. Final mock exam

15–30 questions covering **every goal** in the syllabus, mixing question types and chapters. Each answer is hidden and commented, with a link to the chapter that teaches it. It ends with a diagnosis table:

| If you missed... | Review |
| --- | --- |
| questions 3, 7, 12 | chapter 4 |

## 6. Glossary and index

Glossary: one line per term (definition in one sentence) with a link to where it is explained; in technology and language books, the English term next to it. The index of terms is generated by `build.py` from the concept graph.

## 7. About this book (transparency)

In the README and at the start of chapter 0, in the book language:

> Written with AI (Claude) from the sources cited in each chapter. Checked on <date>. Human review: <yes/no>. Edition <x.y>.

For improved materials, add one line on the original: what it was, and that only its structure, topics and goals were used. The README keeps the history of editions (`build.py` writes it from `editions` in `book.yaml`, filled by `book.py edition` at the end of a review: `modes/REVIEW.md`) and an errata section that points to the repository's "Report an error" form.

## 8. Next steps

At the end of the last chapter: 2–4 suggested books, so the reader knows where to go next. `build.py` writes them from `next_steps` in `book.yaml` (title, why, topics, and a link once a book continues it): keep `next_steps` complete and never write this section by hand. The same list is the starting point of the next book in the track (`modes/CREATE.md` §7).
